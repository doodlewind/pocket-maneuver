# Repository instructions

- Pocket Maneuver owns the world generator and the three.js reference (`web/`), the simulation core (`crates/maneuver-sim`), the world compiler and the pack format (`crates/maneuver-cook`, `crates/maneuver-pack`), the interface (`ui/`, `crates/maneuver-interface`) and the device runtimes (`vita/`, `psp/`, `n3ds/`, `ipod/`, and `crates/maneuver-handheld`, the part the PSP, the 3DS and the iPod touch share). PocketJS (pinned in `vendor/pocketjs`) owns the device toolchains, the Vita dev host and wired debug transport (`tools/vita-dev.ts`, `tools/vita-usb.ts`), VPK packaging, the GXM device kernel (`devices/vita/pocket-vita-gxm`) and the 3DS dev wire (`hosts/3ds/src/devserver.c`, `tools/3ds-dev.ts`).
- Do not edit the submodule to fix application behavior. Send reusable changes to PocketJS, then update the pinned revision here.
- Use Conventional Commits for commits and pull requests (`type(scope): summary`). Publish validated changes as a Draft PR.
- The interface is one PocketJS app, `ui/`, drawn over the scene on every device. A device crate draws only the marks anchored to the world (`Game::draw_marks`: where a wire would bite, the nearest target, the streaks of speed); gauges, lists, text and touch controls go in `ui/`. A device differs by its presentation (`ui/app/presentations/`, chosen by modality in `ui/pocket.json`), not by a fork of a shared part: what a gauge, a row or the map looks like is in `ui/app/parts.tsx` once.
- `ui/app/protocol.ts` and `crates/maneuver-interface` are the two sides of one protocol. Change both in one commit, with `cargo test -p maneuver-interface` and `bun tools/ui.ts test`. The game's flow (title, play, pause, the finished run) is `maneuver_interface::Session`; a device does not keep its own.
- A value that changes in flight goes in the telemetry array `t` and is written with `@pocketjs/framework/hot` into a cell of fixed width and height, text at the left (a write keeps the place layout gave the last value, so centred or right-set text drifts). A Solid signal costs milliseconds per update on the PSP: keep signals for what changes a few times a minute.
- A turn of the guest costs 4 to 6 ms on the PSP whatever it does, so a device takes one only when `maneuver_interface::Pace` says it is due. That rests on the interface reporting `idle` truthfully: a timer in `ui/` goes through `createPulse` (it counts what is pending), and a screen is wrapped in `Keep` instead of being mounted on a mode change.
- Look at every screen with `bun tools/ui.ts preview` before a device build; a change to the interface reports `bench` on the PSP like a renderer change (its turn and its draw are in the status record).
- One rule set, one implementation: gameplay lives in `crates/maneuver-sim` and nowhere else. The reference runs it as wasm (`bun tools/maneuver.ts sim`), the compiler links it for baking rays, every device links it natively. Do not re-implement a rule in TypeScript or C.
- `maneuver-sim`, `maneuver-pack` and `maneuver-handheld` build without `std` (`default-features = false`): `core`, `alloc` and `libm` only. A device crate holds what touches its GPU, pad, sound and storage; anything two devices would both write belongs in `maneuver-handheld`.
- The snapshot layout and the shared constants are generated: after changing `abi.rs`, `sim.rs` constants or the skeleton in `pose.rs`, run `bun tools/maneuver.ts sim` (it rewrites the ignored `web/src/sim/abi.gen.ts`).
- The world derives from one seed. No `Math.random`, wall time or canvas APIs in `web/src/world`: the same code runs in the browser and in Bun for the export.
- Every static surface samples one atlas (`web/src/world/atlas.ts`), so a cell is one draw on the device. A new surface kind is a new strip in that atlas, not a new texture or program.
- A change to the world, the atlas or the bake goes through `bun tools/maneuver.ts cook --profile vita60|psp60|n3ds60|ipod60`; the packs and their compile receipts are outputs under the ignored `.pocket-build/`. A device difference is a profile value or a lowering in `crates/maneuver-cook/src/handheld.rs`, not a branch in the generator.
- The Pocket3D title card plays first at every launch, on each console and in the reference, before the renderer starts: `pocket3d_title::vita::play()` in `vita/src/main.rs`, `title()` in `psp/src/main.rs`, `pocket3d_title_play()` in `n3ds/src/main.c`, `title()` in `ipod/src/main.c` (the iPod touch has no frame buffer a CPU writes: the core draws PocketJS's frames, `mh_title`, and the shell shows them through a texture), `playTitle()` in `web/src/main.ts`. It comes from PocketJS (`vendor/pocketjs/engine/pocket3d/crates/pocket3d-title`): do not skip, shorten, recolour or redraw it here, and do not draw the mark with the game's own renderer. A development run on the Vita skips it with `{"title": false}` in `boot.json`; a `?shot` capture of the reference skips it.
- Keep captures, logs, cooked packs, USB-share contents and build receipts in `.pocket-build/`. Put reproducible commands, results and limits in the PR description instead of committing them.
- Separate evidence kinds when reporting: host build, compile receipt, emulator run (`bun tools/psp.ts emu`), device frame timing (`bun tools/maneuver.ts bench`, `bun tools/psp.ts bench`, `bun tools/n3ds.ts bench`), and what a person saw on the screen. An emulator's frame time is not a device's.
- Shader programs are compiled on the device by SceShaccCg and cached by source hash under `ux0:data/pocket-maneuver/gxp`. Mixing `half` and `float` in `lerp`/`smoothstep` is an overload ambiguity there: cast explicitly.
- The frame budget is 16.7 ms on every device: a PS Vita at 960 × 544, a PSP at 480 × 272, an Old 3DS at 400 × 240. A renderer change reports `bench` before and after; a change that adds a per-pixel texture read or a second pass needs that measurement first.
- PSP: after `pspsh reset`, send nothing until `usbhostfs_pc` logs a new `Connected to device` (`bun tools/psp.ts run` does this with the host `bun tools/psp.ts serve` started). A command sent earlier leaves PSPLINK answering its shell but not storage, and only a restart on the console recovers it.
- PSP: the GE reads a texel before it tests depth, so fill cost is every covered pixel times the texture read. Keep the atlas as palette pages in video memory and the frame buffer 16-bit; a change of texture format or buffer depth needs `bun tools/psp.ts bench` on the console. The pinned rust-psp declares `sceKernelCreateSema` without the bridge that moves a fifth argument into the register the kernel reads, so a direct call answers ILLEGAL_ADDR unless that register happened to hold zero (PPSSPP does not check it): `store.rs` calls it through `i5`. Before using another system function with five or more arguments, check that its declaration in rust-psp names `i5`, `i6` or `i7`.
- PSP: the GE drops a triangle with a vertex outside its 4096-pixel coordinate space. Static meshes go through `Gfx::mesh`, which clips large triangles near the eye on the CPU; geometry drawn another way must stay small or be clipped the same way. Only the frame thread allocates. Host I/O must not be given a video memory address: copy out first.
- 3DS shaders: picasso applies a source's swizzle before the write mask picks components. `mul r1.zw, c.zz, v.zw` reads `v.w` twice; write the source so the wanted value sits at the destination's component (`mul r1, c.zzzz, v`). A skinned model must be looked at close up on the console after a shader change.
- 3DS: installs are `.3dsx` (never a CIA). `n3ds/src/core.h` mirrors `n3ds/core/src/lib.rs` by hand; `mh_sizes` fails the start when a size differs. `tools/n3ds.ts` compiles a source snapshot inside the container, because the shared mount can show a stale size for a file that was just rewritten.
- iPod touch: `ipod/core` is a manifest over `n3ds/core/src/lib.rs`; a change to that file or to `n3ds/src/core.h` is a change to both devices, so build both. On the SGX535 the frame follows the vertices submitted, and a skinned vertex costs about four times a world vertex: a model or skin-shader change reports `bun tools/ipod.ts bench`. Reading the device over SSH costs frames; `bench` lets the app measure its own window.
- The iPod touch is shared between checkouts. `tools/ipod.ts launch` and `bench` wait while another tool has driven the device in the last three minutes; do not bypass that, and never touch another app's bundle or files.
- The mechanic is a pair of wire hooks and compressed gas; the setting is an original walled town, and the giants are an original design. Do not add characters, emblems or names from any film or series.
